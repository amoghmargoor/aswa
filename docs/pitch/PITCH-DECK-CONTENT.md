## Problem Statement (Detailed)

### The $300 Billion Failure

Every year, enterprises spend $300 billion on legacy modernization. 70% of these projects fail or significantly overrun. Why?

**The Conventional Approach:**
```
Step 1: Analyze COBOL code
Step 2: Convert to Java
Step 3: Test
Step 4: Deploy
Step 5: Discover you broke everything
```

**What Goes Wrong:**

1. **Lost Business Logic**: A calculation that adds 0.5% isn't documented in code. It exists because of a 2015 regulatory requirement found in a PDF buried in SharePoint.

2. **Unknown Dependencies**: The batch job must run before another batch job, but this is only documented in a Slack thread from 2019.

3. **Tribal Knowledge**: "We never change that function" - but the person who knew why retired last year.

4. **Compliance Gaps**: The code implements Reg Z requirements, but the new Java code doesn't preserve the audit trail.

**The Root Cause:**

Legacy isn't just old code. It's:
- 40 years of decisions
- 40 years of workarounds
- 40 years of institutional knowledge

This knowledge lives in:
- Documents (Word, PDF, Confluence)
- Tickets (Jira, ServiceNow)
- Conversations (Slack, Email)
- People's heads (retiring workforce)

**Code-only tools fail because they only see half the picture.**

### How It Works: Real Example

**Scenario**: Modernizing `CALC-INTEREST-RATE` COBOL program

**Without Luemyn:**
```
Developer sees: Complex calculation with magic number 1.005
Developer does: Converts to Java, preserves the math
Result: Passes tests, deployed

6 months later: Audit finds calculation doesn't match current
Fed Reserve requirements. $2M fine. Rollback required.
```

**With Luemyn:**
```
Luemyn Code sees: Complex calculation with 1.005
Luemyn Code asks ASWA: "What context exists for CALC-INTEREST-RATE?"

ASWA returns:
├─ JIRA-2847: "Added 0.5% per OCC Bulletin 2015-03"
├─ compliance-requirements.pdf: "Reg Z section 4.2 compliance"
├─ Slack thread: "Auditors check this quarterly - document all changes"
└─ runbook.docx: "Runs after DAILY-BALANCE, before EOD-REPORT"

Luemyn Code outputs:
├─ Java code with compliance comments
├─ Updated documentation
├─ Dependency map for testing
└─ Audit trail of transformation

Result: Compliant conversion, documented, auditable
```
